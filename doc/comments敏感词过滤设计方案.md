# comments 敏感词过滤功能 —— 设计方案（第 9-10 周）

> 对应《comments模块质量分析报告》问题清单 **Q4**（无内容过滤）
> 设计人：杜彬（DB_branch）

---

## 1. 背景与目标

评论正文当前仅校验非空与长度（≤300 字符），任何文字（含广告、辱骂、违规内容）都会直接进入审核队列或前台。本功能在**提交入口**增加一道敏感词检查，使明显违规的内容在提交阶段即被拒绝，减轻审核负担、降低站点运营风险。

**目标**：评论提交时对正文做敏感词匹配，命中即拒绝保存并向用户回显命中词；未命中的评论按原有流程（审核开关）处理。

## 2. 方案比选

| 方案 | 做法 | 优点 | 缺点 | 结论 |
|------|------|------|------|------|
| A. 提交时拒绝 | `form_valid` 中校验，命中则 `form.add_error` 走 `form_invalid` 回显 | 用户即时获得明确反馈；不产生脏数据；复用既有 form_invalid → article_detail 契约 | 词库需维护 | **采纳** |
| B. 命中转待审核 | 不拒绝，强制 `is_enable=False` | 用户无感知 | 用户不知道为何一直不显示；后台审核负担反而加重 | 否 |
| C. 渲染时替换 | 模板层把敏感词替换为 `*` | 不阻止发言 | 已入库内容仍含违规词，无法满足合规诉求 | 否 |

方案 A 与 DjangoBlog 既有的"表单校验失败 → 重渲染文章详情页并显示错误"契约完全一致，无需改动模板与路由。


设计要点：
- **纯函数、无副作用**：输入字符串、输出命中词列表，便于单元测试；
- 词库为模块级常量，集中一处便于替换为数据库/文件加载（预留 `load_sensitive_words()` 扩展点）；
- 匹配前 `str.lower()` 归一化，对英文词不区分大小写；中文子串直接匹配。

### 3.2 视图集成点（唯一改动文件：`comments/views.py`）

在 `CommentPostView.form_valid` 中，文章评论开关校验之后、`form.save(False)` 之前插入：

```python
hits = check_sensitive_words(form.cleaned_data['body'])
if hits:
    form.add_error('body', f"评论包含敏感词：{'、'.join(hits[:5])}，请修改后重新提交")
    return self.form_invalid(form)
```

- 命中最多回显 5 个词，避免长列表刷屏；
- `form_invalid` 沿用原实现（带错误重新渲染 `blog/article_detail.html`），**不改模板、不改 URL、不改表单类**；
- 插入点位于评论开关校验之后，保证"评论已关闭的文章"优先返回开关错误，语义不冲突。

### 3.3 不做的事（边界控制）

- 不新增模型字段、不生成迁移（零数据库变更）；
- 不改 `CommentForm` / 模板 / admin；
- 词库不含管理界面（超出本次范围，见"后续演进"）。

## 4. 测试计划（新增 `comments/test_sensitive_words.py`）

| 用例 | 断言 |
|------|------|
| 纯净文本 | `check_sensitive_words("很好的文章") == []` |
| 命中单个敏感词 | 返回列表包含该词 |
| 命中多个敏感词 | 全部返回 |
| 英文大小写归一化 | `"Spam"` 命中 `"spam"` 类词（若词库含英文词） |
| 视图：含敏感词提交 | 状态码 200（表单回显错误）、`Comment.objects.count()` 不增加、响应含"敏感词"提示 |
| 视图：正常提交回归 | 仍为 302 重定向、评论正常入库（保护既有契约） |
| 视图：回复带敏感词 | 同样被拦截（含 `parent_comment_id` 的提交） |

测试基类复用 `djangoblog.test_base.BaseTestCase`，避免 test_views.py 中的 setUp 复制问题（呼应报告 Q9 的测试改进方向）。

## 5. 风险与回滚

- **误伤风险**：演示词库仅含明确违规词；后续扩充词库时应区分"拒绝"与"转审核"两级策略；
- **性能**：词表规模小（O(n×m) 子串匹配，m=300 上限），提交路径单次开销可忽略；词库扩到千级时可换 Aho-Corasick 或缓存编译后的正则；
- **回滚**：删除 views.py 中的 5 行集成代码即可完全回退，无数据残留。
