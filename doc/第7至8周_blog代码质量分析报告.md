## 2. 主要发现

下表行号为补丁前的基线。严重程度是本项目的处理优先级，实际部署影响需结合路由可达性和运行测试确认。

| 优先级 | 发现及影响 | 源码证据 | 处理状态 |
|---|---|---|---|
| 高 | 详情按 ID 查文章，视图未明确限制发布状态。知道链接的访问者可能读到草稿。现有测试允许 200、302 或 404，无法固定可见性规则。 | `blog/views.py:153–165`、`blog/test_views.py:21–27,141–151` | 待明确后台预览规则，再改查询并测试匿名、普通用户和管理员。 |
| 高 | 清缓存入口直接执行清空，没有应用层鉴权或方法限制。若部署路由可达，外部请求可以反复清空缓存。 | `blog/urls.py:97–102`、`blog/views.py:567–571` | 待确认调用方，再限制到授权后台操作并补权限和方法测试。 |
| 中 | 浏览量先读到对象，再把加一后的绝对值写回。两次访问若读到同一旧值，后一次写入会覆盖前一次结果。 | `blog/models.py:63–79,220–224`、`plugins/view_count/plugin.py:11–15` | 补丁中改为数据库按当前值加一，附回归测试。 |
| 中 | 后台批量发布直接更新状态，不经过模型保存信号。常规保存也只明确删除列表首屏等缓存键。状态改变后可能短时显示旧列表。 | `blog/admin.py:33–49`、`djangoblog/blog_signals.py:118–152` | 待确认全部列表缓存键、归档整页缓存及标签变更时机，再制定统一失效策略。 |
| 中 | 分类树遍历在递归体中反复对 QuerySet 调用 `filter()`，注释称在内存过滤，与实现不符。大分类树可能增加查询。 | `blog/models.py:324–346` | 待用固定树测查询数，再考虑一次加载并按父 ID 分组。 |

## 3. 本轮改进

补丁根据 `1f6ed65` 的差异定位原有个人贡献，在四个核心文件中识别到 395 行有效注释并补上 `# XLT:`，覆盖模块、方法和关键代码说明。单独比较署名版本和原始版本的 AST，四个文件的 AST 相同。随后在 `Article.viewed()` 中改用 `F('views') + 1`，让数据库一次更新只递增浏览量，并更新了相应注释。现有插件仍调用同一个方法，普通模型保存路径保留。方法对尚无主键的对象不执行更新。

验证分三层：

1. 补丁在独立副本通过 `git apply --check --whitespace=error`，应用后五个 Python 文件通过编译检查。
2. 使用内存 SQLite 和替代 ORM 调用的适配器运行补丁前后的实际方法体。两份对象都从 0 读起，分别记一次访问，旧实现最终为 1，新实现为 2，文章标题保持原值。这一实验验证更新逻辑，未覆盖 Django ORM 集成。
3. 新增 Django 回归测试，独立读取同一文章两次并分别调用 `viewed()`，最后从数据库断言计数为 2。本机启动 Django 测试时因缺少 Django 模块而中止，回归测试仍需在项目环境实际运行。

补丁与报告均在本次会话输出目录。验收时可在课程项目根目录先执行 `git apply --check <补丁绝对路径>`，再在个人分支应用。在已装好依赖的项目源码目录执行：

```powershell
python manage.py test blog.test_article_business_logic
```

## 4. 下一阶段优化计划

| 次序 | 改进 | 预期验收 |
|---|---|---|
| 1 | 固定草稿访问规则，检查详情、上下篇链接和评论提交等相关入口 | 匿名访问已发布文章成功，草稿按约定拒绝，授权预览走明确入口。 |

| 4 | 降低分类树查询开销 | 用相同分类树对比优化前后查询次数，并校验子分类范围及展示结果一致。 |
