# DjangoBlog 小组 Python 编码规范

> 软件工程课程实践 · 第 7–8 周 · 供小组评审

## 1. 范围

适用于小组对 DjangoBlog 的 Python 源码与测试的新增和修改。各成员在自己的 app 范围内维护代码，通过小组评审把共同约定应用到后续功能优化。存量文件按本次实际修改范围逐步整理。

## 2. 格式、命名和导入

| 项目 | 约定 |
|---|---|
| 缩进与编码 | Python 文件使用 UTF-8、四空格缩进。每行表达一个主要操作。过长语句优先通过括号拆分并保持可读。 |
| 命名 | 类使用 `PascalCase`，函数、方法和变量使用 `snake_case`，模块常量使用 `UPPER_CASE`。名称说明用途，例如 `published_articles`。 |
| 导入 | 标准库、第三方库、项目内模块分组，每组之间留空行。优先文件顶部导入。确需局部导入来处理可选依赖或循环依赖时说明原因。 |
| 函数 | 一个函数围绕一个行为组织。若同时处理查询、分页、渲染和写入，先确定每部分的边界，再在现有测试覆盖下拆分。 |
| 异常 | 捕获已预期的异常类型，向用户返回符合场景的状态或表单错误，日志保留必要上下文。避免把密码、签名、令牌或完整表单写入日志。 |

## 3. 注释与个人署名

课件要求至少覆盖模块职责、函数或方法、关键代码块或代码行。个人新增的注释以姓名缩写开头，例如 `# XLT:`。多行说明的每个有效行沿用同一前缀。注释说明意图、输入约束、缓存或权限决策，修改业务行为时一并更新对应说明。

```python
# XLT: 让数据库基于当前值累加，避免并发访问覆盖计数。
Article.objects.filter(pk=article_id).update(views=F("views") + 1)
```

## 4. Django 项目约定

- URL 配置定义入口和命名空间。视图处理请求、权限和响应。模型表达数据及其约束。模板负责显示。
- 有写入效果的入口应校验请求方法、登录身份、对象权限和参数。表单校验与数据库唯一约束分别明确。
- ORM 查询以实际访问字段决定预加载。外键通常使用 `select_related`，多对多和反向关系使用 `prefetch_related`。在优化前后记录查询数。
- 用数据库表达式或事务处理依赖当前数据库状态的更新。使用 `QuerySet.update()` 时核对保存信号、缓存、时间戳及搜索索引的影响。
- 缓存设计记录键的组成、过期时间和失效触发点。状态变更验收同时检查首页、分页及可能受影响的聚合视图。
- 用户可见的权限和状态规则在服务端校验。公开页、后台编辑和预览各自明确权限。

## 5. 测试和提交评审

| 时机 | 检查事项 |
|---|---|
| 实现前 | 写明触发条件和期望结果，核对现有测试能否区分正确与错误行为。 |
| 实现后 | 在项目环境跑相关功能测试，并记录命令、实际结果和环境限制。权限相关场景至少检查授权和未授权请求。 |
| 提交前 | 检查差异、注释署名、测试和文档。提交描述说明用户可见变化和验证结果。 |
| 小组合入前 | 由同组成员复核跨 app 影响、数据变更与可复现步骤，按团队实际分支流程归档。 |
