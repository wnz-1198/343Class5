## 3. 功能优化

### 3.1 浏览量原子更新

#### 修改前

```python
def viewed(self):
    self.views += 1
    self.save(update_fields=['views'])
```

两个请求同时读取 `views=10`，分别加一后写回 11，最终结果仍可能是 11，两次访问只增加一次。

#### 修改后

```python
def viewed(self):
    updated = Article.objects.filter(pk=self.pk).update(
        views=models.F('views') + 1
    )
    if updated:
        self.refresh_from_db(fields=['views'])
    return self.views
```

数据库执行 `views = views + 1`，每次更新均基于数据库当前值，避免丢失更新。

#### 验收标准

- 同一对象的两个旧实例分别调用 `viewed()`；
- 两次调用后数据库浏览量为 2；
- 测试见 `blog/test_view_count.py`。

### 3.2 健康检查增强

原接口只返回固定 `healthy`。新接口执行：

1. `SELECT 1` 检查数据库连接和查询能力；
2. 写入并读取短时缓存探针；
3. 返回每项检查结果；
4. 任一关键检查失败时返回 HTTP 503。

示例响应：

```json
{
  "status": "healthy",
  "checks": {
    "database": "ok",
    "cache": "ok"
  },
  "timestamp": 1760000000.0
}
```

接口地址：`/health/`。健康检查不返回数据库异常细节，异常仅记录在服务端日志。

### 3.3 文章 Markdown 导出

#### 用户故事

作为文章读者，我希望下载文章的 Markdown 原文，以便离线阅读、备份或在其他 Markdown 工具中继续编辑。

#### 功能规则

| 访问者 | 已发布文章 | 草稿 |
|---|---|---|
| 游客 | 可导出 | 返回 404 |
| 普通登录用户 | 可导出 | 仅作者本人可导出 |
| 超级管理员 | 可导出 | 可导出 |

#### 使用路径

1. 打开文章详情页；
2. 在标签区域右侧点击“导出 Markdown”；
3. 浏览器下载 `article-<id>.md`；
4. 中文标题通过 `filename*=UTF-8''...` 保留。

#### 导出内容

- 一级标题；
- 分类；
- 作者昵称或用户名；
- 发布时间；
- 标签；
- 原始文章 URL；
- 原始 Markdown 正文。

#### 实现位置

| 文件 | 作用 |
|---|---|
| `blog/services.py` | 组装 Markdown、生成下载响应头 |
| `blog/views.py` | 查询权限范围内的文章并返回附件 |
| `blog/urls.py` | 注册 `export_markdown` 路由 |
| `templates/blog/article_detail.html` | 提供用户入口 |
| `blog/test_export_article.py` | 覆盖公开、草稿、作者、管理员和中文文件名 |

### 3.4 数据库配置改进

原配置直接写入 MySQL 密码。现配置支持：

```text
DJANGO_MYSQL_NAME
DJANGO_MYSQL_USER
DJANGO_MYSQL_PASSWORD
DJANGO_MYSQL_HOST
DJANGO_MYSQL_PORT
DJANGO_USE_SQLITE
```

当 `DJANGO_USE_SQLITE=True` 时使用 `src/DjangoBlog-master/db.sqlite3`，适合自动化测试和课程演示。正式运行仍默认使用 MySQL。

## 6. 兼容性与风险

### 6.1 兼容性

- 新增路由不会覆盖原有文章详情路由；
- 文章模型没有新增字段，不需要迁移；
- 匿名用户仍可访问已发布文章；
- 原有 `viewed()` 调用方无需改变；
- 健康检查地址不变，仅增加响应字段和 503 状态；
- SQLite 开关默认关闭，正式环境仍使用 MySQL。

### 6.2 风险与处理

| 风险 | 处理 |
|---|---|
| 学生本地未设置 MySQL 密码 | 在 IDEA 运行配置中添加 `DJANGO_MYSQL_PASSWORD` |
| 依赖版本未安装 | 按 `requirements.txt` 使用 Python 3.10+ 安装 |
| 中文文件名在旧浏览器显示异常 | 响应同时提供 ASCII fallback |
| 健康检查频繁访问造成探测开销 | 仅在部署平台健康探测周期调用，缓存探针 10 秒过期 |
| 历史注释乱码 | 新代码使用 UTF-8，历史文件后续分批修复 |

## 7. 维护结论

本次维护在保持现有数据库结构和主要页面不变的前提下，完成了并发计数、依赖健康检查、文章导出、配置安全和测试补充。新增功能均由服务端完成权限判断，既没有改变原有公开文章访问路径，也没有把草稿暴露给游客。

项目现在具备更可靠的运行状态反馈、更准确的文章浏览统计和可验证的原文导出能力。第 9—10 周还提供了 IDEA 2023 运行说明、视频讲稿和全 App 手工测试矩阵，方便小组成员继续演示和维护。
